# /knowledge 统一入库

入口是 Web `/knowledge`，调度由 `knowledge/jobs.py` 与 `chunk_index.py` 完成，不经过聊天 Agent。

本文只说明 PEC 知识库 `/knowledge` 入库。Agent 会话中单独上传的 PNG、JPG、JPEG 图片使用 Apollo Vision 生成文字及视觉关系描述；这条图片解析流程不进入 PEC 知识库索引。内嵌在 PPTX、DOCX、PDF 页面中的图片不会因此触发 Vision。

v17 上传暂存与覆盖备份位于资料目录下的隐藏 `.pec-upload-*` 目录，用完即清理，需要预留上传数据和被覆盖文件的额外磁盘空间。隐藏目录不出现在资料目录选择器，暂存文件不参与解析。普通报错有回滚保护；进程强制终止或断电并不具备跨文件原子事务，残留备份需人工核对，不能直接删除。已发布索引的原子切换不受此次上传影响；上传完成后仍需执行入库，原文件历史版本下载尚未实现。

## 使用

1. 上传一场会议的文件夹，或填目标文件夹上传 PPTX、DOCX、PDF、XLSX、ZIP。支持中文文件夹。单个上传文件限制 100 MB；ZIP 解压最多 2000 项、500 MB；一批有效资料同样最多 2000 个文件、总量 500 MB。整批先暂存、校验并备份，再逐文件替换；无效路径、重复目标或损坏 ZIP 不会先覆盖已有文件。替换遇到存储错误时恢复已替换文件；恢复也失败时保留暂存备份并返回 503，需管理员核对。
2. 选择该文件夹，点 **解析检查（不调用模型）**。查看文件片段数、图片/图表/扫描页提示。检查不会写入正式索引、不会调用 Apollo。
3. 点 **开始入库**：原生解析 → 清理图片标记并保存 MD → 文档级 topic 抽取与整合 → 原文/topic 统一 embedding → 发布完整版本。此步骤需要现有 Apollo 配置和网络。关闭页面任务继续，重开页面能看到记录。
4. 在「查看已发布 Topic 与证据」面板核对结构化字段和引述；也可回到聊天检索。失败时仍使用上次成功发布的索引；可重新提交同一范围。服务重启会将未完成任务标记为中断，不自动重试付费调用。

服务器直接读取仅限 `KNOWLEDGE_SOURCES_DIR`，不接受浏览器提交任意服务器绝对路径。可把一场会议复制进该目录的子目录，刷新后选择它。该路径下的资料可通过现有来源下载 API 访问，应仅放拟公开给本系统用户的资料。

知识库 LLM 调用默认超时 300 秒，可通过 `APOLLO_INGEST_TIMEOUT_SECONDS` 设置为正数；网络、超时和网关 408/409/429/5xx 错误最多额外重试两次。

## 存储与兼容

- `KNOWLEDGE_ROOT` 默认 `data/pec`；原文件默认在其 `sources/`，索引在 `index/`。为兼容旧部署，未设置 `KNOWLEDGE_ROOT` 时仍读取 `PEC_KNOWLEDGE_ROOT`。也可分别指定 `KNOWLEDGE_SOURCES_DIR` 和 `KNOWLEDGE_INDEX_DIR`。部署时在**进程启动环境**设置路径，例如 PVC 挂载 `/data/knowledge` 并设置 `KNOWLEDGE_ROOT=/data/knowledge`。
- 新索引存于 `index/generations/<id>/{manifest.json,chunks.jsonl,embeddings.npy,topics.json}`。仅在所有阶段成功后原子替换 `index/CURRENT`。读取方一次固定一个版本，避免混读旧向量和新原文。尚未发布过新版本时兼容旧的 index 根目录文件。
- `index/jobs/*.json` 保存任务和文件检查记录，`writer.lock` 防止上传与索引写入并发。当前采用单服务内后台线程，不是外部队列。先部署单副本，PVC 必须支持文件锁和原子 rename；未验证公司集群。多副本/分布式 worker 需后续换数据库任务队列及分布式锁。
- SHA256 与解析器版本判断是否需要重解析；同 embedding 模型下按完整文本复用已有向量。重算向量针对整个已发布索引，忽略文件夹选择；保留已有 topic，不触发抽取或视觉识别。旧版文件第一次完整更新会按新版解析配方重新处理。
- 扫描时不自动删除磁盘上暂时消失的已索引文件，避免挂载或同步异常误删。已提供缺失检测、人工触发的撤销同步与恢复；旧版本清理、任务历史分页后续补充。当前保留旧版本会持续增加磁盘占用。
- 原文件上传为原子覆盖，不保存历史原文件；失败时旧索引文本仍可用，但下载原文件可能是更新后的版本。后续要将原文件也按版本保存，以支持历史引用。
- POST `/api/knowledge/jobs` 返回 HTTP 202 和 `job`；GET 同路径返回最近 20 个任务。旧 POST `/api/index/update` 现为相同异步接口，调用方应轮询任务，不能再把 202 当成已入库。

## 原生 MD 与文档级 topic（2026-09-28）

知识库入库不调用视觉模型或 OCR。python-docx 提取正文和表格并保留交错顺序；python-pptx 提取文本框、组合形状中的文字和原生表格；pypdf 提取文本层。保留单行表格和短决议。图片内文字、扫描页、图表的视觉关系不补全；PDF 的复杂排版阅读顺序仍需样本检查。XLSX 原有单元格解析保持可用。知识库上传只接受 PPTX、DOCX、PDF、XLSX，不接受独立图片文件。

清理发生在生成证据 ID、切分、topic 和 embedding 之前：删除 Markdown 图片（含引用式）、HTML img、图片注释、独占一行的图片占位符，不删除正文中正常提到“图片”的句子；表格单元格在序列化前也清理。图片 alt 文本不作为事实。清理后的有序证据写入 `index/parsed/<hash>.md`，文件 manifest 的 `markdown_path` 给出相对 index 的路径。该文件是可检查的解析产物，不表示索引已发布。MD 和模型输入均带页面/段落/表格位置及证据编号；模型使用短编号，验证后恢复真实 chunk ID。

部分页面没有文字会跳过并在诊断中提示。整份文件无文本时标为 `skipped_no_text`，不调用 topic 或 embedding，不阻塞同批其他文件。重新入库此文件时移除其旧 chunk 和旧 topic，即使最终索引为空，也发布合法空版本；旧 generation 保留。损坏、无法打开或加密解析失败仍作为错误，不伪装成空文件。预览仅供人工查看，可用 `PREVIEW_ON_INDEX=0` 关闭；缺少 Office/LibreOffice 不再阻塞文本入库。

普通文档以全文生成 topic（约 48000 字符证据预算），合并同一文件跨页、跨章节的背景/请求/决议/行动。超长文档或输出截断采用候选抽取后全文整合；不直接拼接批次结果。整合模型只返回候选分组，程序验证每个候选恰好出现一次，再保留全部原事实及引用，仅去掉完全相同的事实。不同研究、适应症和不确定关联的候选保持独立。移除旧的每字段最多 3 条事实限制。字段不合格时由程序就地修正：空列表、超长标题、超长 text 或 quote 会截短并保留原事实，不因此重抽或丢弃整段。只有 JSON 不完整、输出被截断且缩小后仍无法抽取时，才跳过该片段；同文件的其他批次和其余文件继续入库。全文整合校验失败时不中止发布，各批候选分别保留。

每条事实继续附 evidence_id 和连续原文 quote，校验不允许删改事实绕过引用检查。保留日期、否定、条件和委员会层级，不根据 decision 反推缺失的 for_endorsement。Schema/逐字匹配和候选覆盖检查不能替代真实模型的语义验收。

解析器版本更新为 5，缓存配方为 pec-business-qc-meetings-v1。升级后对所需目录执行普通“开始入库”即可按新规则重建，无需清缓存；仅重算向量或补标签不会迁移旧 topic 内容。未重建范围继续使用其旧版本。成功的 topic 抽取和全文整合按文件内容、证据、模型及配方缓存。topic/标签使用 APOLLO_MODEL，向量使用 APOLLO_EMBEDDING_MODEL；APOLLO_VISION_MODEL 只用于 Agent 会话中单独上传的 PNG、JPG、JPEG，不参与知识库入库。跨文件新增会议级整合视图；文件级的同名关联候选作为兼容信息保留。

所有结果写入同一个 generation 后才切换 CURRENT。topic 同时作为带 evidence_ids 的检索片段进入统一向量索引，命中后补回支撑原文。新 topics.json 存在时聊天停止调用旧 topic SQLite 检索；旧数据库文件不会修改或自动迁移。此前未纳入统一入库的旧 topic 需重新导入其原始资料。`GET /api/knowledge/topics?scope=会议目录&offset=0&limit=100` 可分页查看已发布结构化结果。

## PEC 规则、独立质检与会议级整合（2026-09-28）

业务规则来自 `input/input/PEC-structurer/step1-parse.md`、`step2-merge.md`、`step3-quality-check.md` 和 `reference-fields.md`，在 `topic_quality.py` 中明确实现：实质议题识别、噪音/纯进度过滤、study number 与 asset+indication 区分、委员会层级及状态、流程审批与会议决议的字段边界、请求编号项、行动负责人/期限/完成状态、日期与原文证据。

保留三项有意差异：不从 decision 反推 for_endorsement；有实质请求/决议/行动时不因缺少 background 而删除；raw_source_text 用已关联的原文 chunks 提供。空字段表示未明确记录，不生成无引用的“尚无决定”。不同来源的冲突不覆盖删除。

每个文件证据批次抽取后调用独立文本模型做质检，输入包括未被初稿引用的原文，以补回遗漏并修正字段。质检按议题筛选：整题都是纯标题、无对象 TBD 或仅有进度且没有风险、请求、决议、行动时，记录排除理由后不进入索引。个别字段不明确时保留该题，并在报告的未解决问题中备注，不因此停止发布。检查项能记则记，缺项不否决。程序仍核对逐字引述和排除理由；实质请求、决议、行动不能无声删除。单题输出截断、引用无效或调用失败时保留该题的抽取初稿并写入报告，其他议题继续。成功质检缓存，普通重试可复用。`index/quality/<hash>.json` 和同名 `.md` 保存质检报告，文件 manifest 的 `quality_report` 指向 JSON。报告及模型检查不等于已通过人工语义验收。

用户确认“一场会议一个文件夹”：仅在直接父目录内整合，不跨日期目录、子目录；散放在 sources 根目录的文件不自动视为一场会议。更新指定目录时只重建该范围的会议计划，其他范围保持原计划。每个会议以优先级最高的文件为框架，通常是纪要，其次是行动清单、更新稿、议程；草稿纪要不作为框架。来源类型按文件名判断。框架里的议题直接成组，其余文件的议题逐条对照，每次只判断一条是否并入已有议题。研究、适应症或事项不能确认相同就单独成组。对照失败也单独保留，不中止发布，也不在这一步丢弃实质议题。每组保留合并依据；跨文件事实明显矛盾时保留冲突说明。文件级质检已经完成，会议对照不再重复 18 项检查。

文件级 topic 继续写 `topics.json` 并与原文 chunk 共用索引。会议分组计划写入同一 generation 的 `manifest.meeting_plans`，其中保留文件 topic 成员 ID；程序按来源顺序组合事实，不让模型改写原有决议。相同文件名不同格式的完全相同事实合并展示，保留所有来源引用；不同内容继续保留。同一 generation 的 `meeting_topics.json` 保存当前可见结果快照。会议冲突提示属于模型的整理判断，应对照原文核验。

会议级结果不重复生成向量：检索仍通过文件 topic/原文召回，再展开对应会议的决议、请求、行动及证据。来源撤销、恢复或缺失同步会按成员关系重新组合并原子发布会议快照，无需再次调用模型或 embedding；撤销来源的事实和失效冲突不得继续出现。文件内容更新后，下一次入库重新质检和整合。标签筛选只允许匹配的文件 topic 成员进入会议视图及检索展开，不扩大到同会议所有资料。

页面的“会议整合 / 单个文件”选择器切换视图。API `GET /api/knowledge/topics?level=meeting&scope=会议目录` 返回会议级 topic、各事实来源、证据和冲突；默认 `level=file` 保持已有客户端兼容。旧资料需执行完整入库以获得新版文件质检与会议视图，补标签或仅重算向量不能代替迁移。

## SharePoint 扩展位置

`sources.py` 的 `SourceProvider.discover(scope)` 返回 `SourceDocument`：本地路径、source_ref、provider、external_id。解析/索引仍只读本地 sources，不直接访问 Graph。

知识库页的“SharePoint 入库”在配置了 `SHAREPOINT_TENANT_ID`、`SHAREPOINT_CLIENT_ID`、`SHAREPOINT_CLIENT_SECRET`、`SHAREPOINT_SITE_URL` 后，可以浏览站点文档库文件夹。本地写在 `src/.env`；OpenShift 从 chart Secret 和 ConfigMap 注入同名变量。`GET /api/knowledge/providers` 在未配置时仍是 `entry_only` / `can_import=false`，且不访问远端。`GET /api/knowledge/sharepoint/folders?path=` 列出当前层文件夹和文件。`POST /api/knowledge/sharepoint/import` 把所选文件夹（含子文件夹）里的 PPTX、DOCX、PDF、XLSX 下载到 sources 的同名相对路径；大小相同的已有文件会跳过。下载完成后再用原有“检查并入库”。应用凭据只放在环境变量，不写入代码或接口响应。

尚未实现：按 drive item / eTag 的增量游标、ACL 过滤，以及远端删除或权限撤销同步。

## 验证

在 `src` 运行 `python -m unittest discover -s tests -v`，使用临时资料与 mock embedding，不读真实会议或调用模型。前端在 `src/web` 运行 TypeScript 检查和 Vite build；`tests/knowledge-smoke.cjs` 通过 Playwright + Edge 验证独立任务页面，可用 `PLAYWRIGHT_MODULE` 指定 Playwright 路径。

## 文件撤销、缺失同步与恢复

/knowledge 的「管理已入库文件」显示文件是否仍存在，以及 active/withdrawn 状态。「撤销检索」发布一个新索引版本，将该源文件从后续关键词/向量检索、topic 列表及关联证据中排除；不会删除原文件、历史索引、缓存或已生成的聊天记录，也不是下载权限控制或安全擦除。已经开始的检索仍使用其固定版本，下一次检索才读取新状态。

「同步移除缺失文件」是核对后的显式操作。后端会重新检查文件确实不存在再撤销，避免把临时断开的挂载当成大量删除。它不是无人值守的 SharePoint 删除事件消费器。恢复前必须放回与入库 SHA256 一致的原文件；内容已更改的资料可用新文件名重新入库。普通/强制入库不会偷偷恢复已撤销文件。

GET /api/knowledge/sources?scope=目录 返回状态；POST /api/knowledge/sources/state 接收 source_ref 与 action（withdraw / sync_missing / restore）。操作与入库、上传共用写锁，不需要模型调用。物理删除、自动删除策略与未来 SharePoint 权限撤销另行实现。

## 跨文件 topic 关联的范围

标题采用 Unicode 标准化、大小写及标点归一化；只关联同一个直接父目录下、来自不同文件、标题相同的 topic，并排除太短及部分泛化标题。同一个目录是用户组织的范围，不代表系统识别出了会议日期。不同标题即使语义相近也暂不自动关联。

前端展示关联文件；命中 topic 时可附带其他文件的最多六条事实引述，明确标为“同名议题关联候选，未独立重排，不代表同一决议”。撤销文件后自动从关联中消失。该关系根据当前已发布 topic 动态生成，无需重入库或额外模型调用。

## Topic 历史修复摘要

Topic 输出修复：独立使用非流式调用；议题抽取和全文整合的输出上限为 16384 token，与单题质检相同。检测长度停止及不完整 JSON，最多两层拆批重试，单个长证据可带重叠拆分并保留 evidence_id。最终仍校验逐字引用；失败不发布残缺索引。41 项离线测试通过，公司模型效果待验收。

Topic 引用修复：向模型提供 E001 等短证据编号，验证前恢复原 chunk_id。只接受原文中的连续引述，空白和等价标点可以还原到原文字符，不模糊匹配数字、词语或翻译。引述若只标错了页码、但在本批次另一处原文唯一出现，改用那一处的 evidence_id。引用失败最多再请模型修正一次，且不允许它删除或改写事实。修正后仍无法定位的，只去掉那一条事实，其余议题继续；只有整批都无法定位时才跳过该批次。topic 请求使用新的缓存键。引用存在性不等于语义支持性。

Topic 字段校验修复：JSON 语法正确但类型、字段名或长度不符合 Schema 时，保留具体字段路径/错误类型并修正一次；仍失败进入有限拆批。禁止通过删掉原先可识别事实或议题满足数组上限。该修复不恢复旧业务标签字段；primary_category、secondary_category、ta、indication、confidence、reason 仍待单独元数据流程接回。50 项离线回归通过，覆盖截断后 schema 错误的组合情形。

## 标签步骤已取消

入库不再调用分类模型，也不再提供「补充缺失标签」。议题、原文和会议整合照常发布。检索默认覆盖全部已发布资料，不按业务类别、治疗领域或适应症排除内容。`tags_only=true` 的任务请求会直接拒绝。
