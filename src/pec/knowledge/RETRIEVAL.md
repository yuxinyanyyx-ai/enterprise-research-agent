# 统一索引检索更新

适用于 /knowledge 发布的统一索引，也可读取旧 chunks/embeddings。无需为检索算法本身重算向量；要使用文档级 topic 并移除旧视觉证据，需对原资料执行新版完整入库。

## 流程

1. 固定一个已发布索引版本，严格按显式资料目录及子目录过滤。A 不会匹配 AB；不根据 LLM 猜出的标签排除原文。
2. 向量召回最多 40 条；同时对原文、topic 和文件名做 BM25 风格关键词召回。英文保留试验编号等组合词，中文使用二字片段。此实现不是语言学分词或独立搜索引擎。
3. RRF 融合两路排名，给原文和 topic 都保留候选席位，最多送 60 条给 Apollo rerank。阈值沿用 RERANK_MIN_SCORE（默认 0.4）。
4. 相同文件内相同文本去重；优先每文件最多两条，剩余名额再补齐，默认返回最多 8 条。不同文件的相同措辞保留，避免删除会议版本差异。跨文件多样性是软规则，不能保证检索齐全六年的历史。
5. Topic 命中补回逐字支撑引述；短 DOCX 段落补充前后段作为上下文，并明确标为未独立重排。
6. 默认上下文预算 24000 字符，可用 RETRIEVAL_CONTEXT_CHARS 调整到 4000–60000。尽量保留完整文本，超预算时保留开头、末尾及查询词附近，并明确标出省略。不是固定截取前 500 字。

## 内置扩词与有限补充检索（v16）

扩词直接内置，没有前端或环境开关，不需要重新入库。BM25 本身仍按词匹配，查询层负责提供更多表达。

- 原问题始终是一条独立召回路线。内置少量中英文搜索词，如“延期 → extension / delay”、“申报 → submission / filing”、“临床试验 → clinical trial”。这只是搜索词表，不是解释决议的同义规则，也没有覆盖所有领域缩写。
- 主 Agent 可以在现有工具调用的 `recall_queries` 参数中提供最多两条别称或等义表达；不新增专门改写模型调用。新增词不能改变研究编号、否定、日期或条件，也不能当作原文事实。所有扩展都追加到完整检索问题后，总计最多三条关键词召回路线。
- 关键词文档只分词一次，复用词频；扩展路线以 0.3 权重参与 RRF，原问题关键词和向量路线各为 1。候选预算内为各路线的前两条保留少量位置，最终最多 60 条统一按原问题 rerank，沿用原相关性阈值。每次搜索仍只有一次 query embedding 和一次 rerank，不按扩展数翻倍。
- 首次证据充分时直接回答；缺少明确日期、条件或来源时，现有 LLM 可发起一次针对缺口的补充搜索。harness 强制最多两次实际检索、拦截重复调用、保持首次目录范围，并把首次完整检索问题传给后续重排。各轮证据都留在模型上下文和引用事件中；第二轮无新增证据时说明缺口，不继续搜索。停止条件的语义判断由现有 LLM 做，次数和重复限制由代码做。
- 被跳过的搜索明确显示原因，不把上一轮引用或命中数当作新结果。兼容的旧 SQLite topic 路径仍保持原算法；扩词适用于正式统一索引的关键词召回。

离线 A/B 用相同合成索引、固定模拟向量和模拟重排，对比旧单查询与内置扩词：“延期 / 临床试验 / 申报”三组中英文表达差异均从未命中变为命中目标原文；每次仍一次 embedding、一次 rerank。另测范围约束、否定保留、候选预算、重复/次数限制和多轮引用。这证明代码路径工作，不代表真实模型或会议问答准确率。公司 OAuth 网关本次连接超时，真实模型评测仍需在公司网络完成。

## 失败和回答行为

- 查询模型与入库模型不同、向量缺失或 embedding 失败：仅用关键词候选，并显示降级提示。
- rerank 异常：使用融合排名，分数记为空，明确相关性尚未确认；不会伪装成通过阈值。
- rerank 正常但没有达标结果：返回证据不足，不用低分结果凑数。
- 搜索工具把降级原因传到执行步骤和回答上下文。原文来源面板保留所有返回的最多 8 个命中及 topic 支撑引述。
- 回答不再固定三个 Point，也不默认补充资料以外的临床意见。保留条件、否定、会议日期、draft/final、待批准/已决议以及冲突来源；未知就说明当前证据不足。
- 新 topics.json 存在时不再调用旧标签+SQLite 检索。旧库兼容查询只在未发布新 topic 且没有指定目录时使用；有目录范围时不调用不支持可靠目录过滤的旧库。

## 验证与下一步

离线回归覆盖编号漏召回、中文关键词、目录边界、模型异常、重排无命中、短决议上下文、多文件多样性及预算内保留中段/尾部证据。入库、引用与前端回归一并运行。

这些测试验证算法行为，不代表实际会议问答质量已经验收。下一步拿一场真实会议，准备约 10–20 个问题与应命中的文件/页码，分别记录召回、最终引用、回答事实、延迟和调用量；再调候选数、阈值与预算。六年规模下还应增加持久化倒排索引、索引版本缓存和可复用评测集。目前关键词扫描及向量加载仍随资料量增长，未做大规模性能验收。

文件管理更新：撤销状态在召回之前过滤，topic API 和关联证据同样过滤；存在撤销来源时，不能可靠过滤状态的旧 topic SQLite 检索也不调用。仅同目录同名 topic 可补充跨文件关联候选引述，不自动合并决议。

检索行为同时写入 src/agent_skills/knowledge-qa/SKILL.md 和 src/skills/knowledge_tools.py：首轮保留完整问题、允许针对缺口补充检索、包含 topic/视觉证据、遵守显式范围和引用/冲突规则。更新包需要同时同步这两个文件。

入库不再为 topic 生成业务类别、治疗领域或适应症标签，检索也不依赖这些标签。历史索引里已经写进检索文本的旧标签会保留到该文件下次重新入库。

## 新旧 topic 流程核对（v9，2026-09-24）

用户已确认本轮保留当前检索架构，只修可靠性问题；没有恢复自动 query 标签硬过滤，也没有新增隐式分类过滤。

旧入库由 `src/input/input/PEC-structurer/` 的分步 Skill 处理预先转换的 Markdown：逐文件提取 → 以 meeting minutes 为基础，按 study number / asset + indication / topic 名称关联并合并 → 质量检查 → 结构化 Markdown。随后 `parser.py` 解析 topic，`tag_topics.py` 并发打类别/TA/适应症标签及生成 background_summary，写入独立 SQLite。另一路原文 chunk embedding 索引与此独立维护。Skill 描述的是预期人工/Agent 工作流，不是已接入新版后台的自动任务。

当前入库直接从本地 Office/PDF 开始：原生解析 → 清理图片标记并保存 MD → 文档级 topic 抽取与全文整合 → 独立分类 → 原文、topic 共用 embedding 与原子索引发布。原文 chunk 保留并与 topic 共用清理后的有序证据；DOCX/PDF/PPTX 不再进行视觉识别或 OCR。分类失败可标为待补充，核心事实/引用校验失败则不发布新版本。

旧检索 `src/search_api/search_api/retriever.py` 和 `engine.py` 的实际次序：

1. LLM 给用户问题打分类标签。
2. SQL 用问题的主/次类别与 topic 的主/次类别交叉匹配。代码里的 TA/适应症条件被注释，未实际启用。无有效类别、或一个候选都没有时回退全部 topic。
3. 候选分为最多三个并发批次，让 LLM 逐条判断 relevant=1/0。单批候选数没有固定上限；某批异常会丢弃该批结果。
4. 按命中的 source_file + topic_id 回取完整 background、endorsement、decision、todo、raw_source_text，交给主 Agent 回答。

当前检索也分阶段：原文/视觉/topic 的向量与关键词召回 → 排名融合（候选中保留原文和 topic 名额）→ rerank 和阈值 → 去重及来源多样性 → topic 原文引述、邻近段落、同目录同名议题关联候选 → 主 Agent 回答。显式标签筛选仍可能遗漏未标注资料，默认不限。已发布统一 topics.json 后，不再并行运行旧 SQLite 路径；它仅保留在尚无统一 topic 索引且无范围/标签/撤销限制的兼容场景。

取舍：旧版适合已整理好、分类稳定的 case 库，会议级 topic 汇总更完整，LLM 逐项相关性判断可以表达细致业务规则；但问题分类错误且恰有少量错误类别命中时不会回退全库，可能漏掉真正相关的其他类别。其候选批次随历史数量增长，成本和截断风险也增长。新版更适合当前杂乱资料的自动增量入库，原文作为兜底，引用更易核对，重排候选有上限；但 top-k 仍可能漏召回，严格引述校验也会带来失败重试，不能仅凭架构断言准确率更高。

旧会议级合并目前没有等价迁移：新版只是逐文件 topic 和同目录同名关联，不会按 study number / asset + indication 自动生成合并 case。旧 Skill 还允许从 decision 反推 endorsement；新版不做这种推断，缺失字段留空。未来若需要会议总览，应在保留原始 topic/引述之上单建可追溯聚合层，不覆盖原始决议。本轮未增加该层。

建议验收用同一场会议的 10–20 个问题（明确分类、跨类别、药物/适应症缩写、需要多文件、无答案），记录正确文件/页码、漏召回、误召回、引用准确性、耗时和调用量，再决定是否增加自动标签的辅助召回；不能把模型猜测标签作为唯一入口。

v9 引用卡片固定展示本次检索命中的索引片段，不再临时读取可能被覆盖的原文件来替换证据。原文件下载仍指向服务器当前版本，尚不是历史版本下载。

## 会议整合检索（2026-09-28）

文件级 topic 与原文共用原索引。命中文件议题或其原文证据后，可展开同一会议分组的请求、决议、行动和来源冲突提示；不会跨直接父目录合并。会议分组来自独立质检后的文件议题，计划随索引版本发布。展开时重新应用来源可见性、目录和标签筛选；撤销/恢复后不引用隐藏来源。模型冲突提示不是原文事实，回答需核对各来源、委员会、日期与条件，不能自动消解冲突。
